# 双方案本地假设对照

preview.31在决策比较内增加「双方案本地假设对照」。适合比较同一份方案数据、同一套确定性规则在两组条件下的结果，复用现有中文表单、结果包和个人模板。

## 使用

1. 调整当前本地条件，点击「保留当前条件为A，开始编辑B」。A记录此时**已应用**的条件、关注维度和本地偏好探索开关；未应用草稿仍独立留在B中。A不自动变成原始来源或批准。
2. 在B用原有批量表单或快速控件调整条件。表单仍须先校验、预览差异再应用。并排查看A/B的满足、排除、未知方案及规则状态；条件表保留原始声明、A、B和声明依赖范围。
3. 展开逐项需求或排除条件，核对实际值、所需值、状态和规则编号。相同计算核心分别计算两份快照；字段匹配、给定政策和本地结果不认证现实事实。未知价格/能力不会因修改需求而补齐。
4. 点击「恢复方案A（保留B）」只读查看A的原有状态。B的已应用值、关注维度和未应用草稿仍保留；点击「回到方案B继续编辑」继续。关注维度只影响展示，条件变化也可能不改变最终结果状态，例如仍未跨过同一个阈值。
5. 点击「保存双方案到当前配置」另存新结果，或在「保存与携带完整结果」中导出完整JSON。刷新后读取、选择并打开保存结果，A/B、当前查看哪一份及B草稿一起恢复。另一兼容环境导入后仍可切换、编辑和再次保存。

「取消草稿」只取消未应用编辑；A及B已应用值不变。「退出对照，保留B」回到普通B试算，放下当前未保存的A快照；以前保存的结果不被改写。普通重置条件只重置可编辑B，不修改A。需要长期保留A时请先明确保存。

## 保存与边界

新结果格式3只增加有界A快照和当前查看标记；B继续使用原有本地条件/选择和独立草稿，不重复保存整份来源或建立另一套聊天库。A最多12个现有字段，数字、是/否和有限选项按原协议逐项核验，非法字段、值或选项不以默认值替换。整体仍沿用结果包128KiB、当前profile最多20份/2MB。

preview.31读取旧preview.28格式1及preview.30格式2，旧文件本身不改写；旧格式不能夹带新对照字段。格式3需要31或兼容接收端，回退前须保护新结果和旧库备份。导入数据不当作新指令、作者、权限或批准，也不自动提交来源补充、工具或模型请求。

模板继续只保存字段合同和外观；当前数据、A/B假设和来源记录属于结果包。两个方案共享原始数据/单位和当前外观，字段标签、来源文字与模型注释保留原文。A/B的本地偏好探索开关各自保存，均不构成政策批准。

## 新增验证

`pnpm typecheck`、`pnpm test`覆盖严格快照和旧格式读取；冻结干净源码后运行`pnpm release:pack`和`pnpm test:installed-scenarios`验证实际安装包。公开合成例给出独立预期：容量120/300、维护可用性原未知，B需求200/维护可用/高并发时仅自管方案满足条件；关注维度变化或同一阈值内100→101不凭空改变结果；null、0和false分别处理，原价格未知保留。

隔离真实DSH的Native/PTC只检查新增路径，包括A只读、B草稿、条件/结果对照、恢复A仍保留B、保存刷新重开、两个干净profile间携带后继续、旧28/30结果读取、格式伪装/坏A拒绝、640/360容器及页面错误。它们不是自然模型、用户Edge、真机、读屏或Codex富UI验收；0新增自然模型回合，旧六题失败保留。最终不可变工件、公开下载与个人入口采用的状态在冻结后的接受记录单列，脚本存在本身不代表已通过。
