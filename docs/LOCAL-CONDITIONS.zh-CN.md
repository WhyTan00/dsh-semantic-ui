# 批量编辑本地条件

preview.30在决策比较内增加「批量编辑本地条件」。数字、是/否和有限选项共用一个中文表单；原来的快速条件控件仍可使用。

1. 展开表单，填写草稿。每项都能明确「保留未知」；空白、无穷大、非数字和不存在的选项会显示错误，不能被当作零或自动应用。
2. 点击「预览差异」，核对原始声明、当前本地值和待应用值，以及应用前后的满足、排除、未知方案。偏好规则沿用原来的显式探索开关；没有排序依据时不会新增排名。
3. 点击「应用到本地试算」一次应用全部有效字段。修改草稿、快速条件或偏好探索后，旧预览失效，必须重新预览。「取消草稿」不改变已经应用的值；「按原始声明重填」只填写草稿，仍需预览和应用。
4. 点击「保存草稿到当前配置」另存为一份完整结果，即使有输入错误也可保存。刷新后在「保存与携带完整结果」中读取、选择并打开它，就能继续修改。普通结果保存同样包含草稿。未显式保存的编辑刷新后复位。
5. 「导出完整结果」携带原始数据、本地已应用值和独立的草稿。另一兼容环境导入后仍需预览和应用，不会把错误文本写进当前计算，也不会把导入数据当成新的来源、身份或指令。

原始来源、原始声明、模型注释、已应用的本地假设和未应用草稿分别保留。只调用原有确定性条件计算，不调用模型、不提交工具动作、不修改来源；条件变化不会补齐方案中未知的价格或能力。模板只保留字段合同和外观，不包含这次的数据或草稿。

新结果导出使用格式2。preview.30继续读取preview.28的格式1，不改写原文件；preview.28不支持格式2，应先升级接收端。格式1中不能夹带格式2草稿字段；未知版本和不兼容依赖仍拒绝。当前输入上限12项，有限选项上限12项，草稿文本上限80字，沿用完整结果的128KiB和当前profile的20份/2MB限制。来源容量上下文的本地需求另外遵守原有容量范围。

打开或导入结果时，文件里记录的语言仅是保存记录，不覆盖当前浏览器选择的「简体中文 / English」。顶部入口始终显示「界面语言 / Language」，选错语言也能识别；默认简体中文，显式选择随刷新保留。

验证命令：`pnpm typecheck`、`pnpm test`，冻结干净源码后运行`pnpm release:pack`和`pnpm test:installed-local-form`。新增定向检查覆盖真实DSH隔离Native/PTC、四个多类型条件、错误草稿保存重开、预览后原子应用、失效预览拒绝、未知/零、取消/重填、旧格式1英文记录不覆盖中文、两个干净profile之间携带草稿、640/360容器及页面错误。它们是合成夹具验证，不是模型自然题、用户Edge、真机或读屏验收；原自然题失败保留。最终工件与公开发行状态见接受记录，源码中的验证脚本本身不构成通过。
