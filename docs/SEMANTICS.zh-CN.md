# 可计算的要求与可审阅的偏好

本轮修复的是程序能够负责的语义边界。模型的完整自然语言、来源声明与业务判断仍需分别核对，不能承诺所有模型、问题和设备都完美。

## 从数值事实计算要求

协议 1.2 的数值维度声明 `kind: "number"` 和明确 `unit`，选项值为有限数字或 null。`requirements` 将一个维度与一个本地数值输入关联：`at-least` 表示选项值 ≥ 需求，`at-most` 表示选项值 ≤ 上限。单位必须完全相同，不自动换算。条件未确认或源值未知时保留 unknown，不当作 false 或 0。

布尔能力使用 `kind: "boolean"`、true/false/null 与 `relation: "supports"`，没有数值单位。需要私网时，不支持的选项被排除；不需要时该要求不生效，未知能力保持未知。所有本地输入都必须连接要求、约束或偏好规则；没有作用的装饰控件被拒绝。

容量 100GB / 1000GB 与当前需求 80GB 比较，两者满足；当前需求改为 300GB，100GB 选项被排除。若未来需求已确认才生效，使用显式激活条件；未来需求改成 50GB 后重新计算 50，不沿用“300GB 不够”的固定解释。当前需求不能被遗漏为只检查未来条件。

可行性仅对应声明的硬要求。满足容量不证明部署、维护、成本或迁移更优，也不说明原始数值已获独立核实。未知选项价格不会因为输入预算上限而变成已知价格。

## 偏好与来源标签

所有新版本偏好规则默认待审阅，包括模型标成 `origin: "given"` 的规则。来源字符串不能自动授权推荐，省略未知比较项也不能绕过这层保护。原比较维度和模型说明保留，前台首先显示程序从结构化数据计算的摘要。

用户可在本地勾选 **Explore preference policy (unverified)**，探索模型提供的假设规则。硬要求始终排除不满足的选项；比较值仍未知时暂缓偏好结果。勾选不发模型请求，重置/刷新即撤销，不写回源事实或模板。它不代表规则或其来源已被验证。

规则文字说明是固定的定义，当前谓词与数量检查由程序重新呈现。条件变化后不把旧文字当成动态推理。完整历史 1.0/1.1 保留原有行为；新交付统一使用 1.2 保护，不能通过要求旧版本绕过。未知版本仍拒绝，不静默改写旧日志。

## 图的计算范围

`graphFacts` 从实际节点/边计算共享有向目标与路径交集。例如 API→Queue→Worker→Database 和 API→Database 两条路径共同包含 API 与 Database。只保留声明方向，不补反向路由。没有边不能证明禁止、唯一所有权、隔离或故障独立；单向边不能证明重试与回滚策略。

前台增加可展开的计算检查，模型的摘要、节点说明和场景解释有明确来源标记。长列表有界并记录省略数。程序证明的是载荷内的结构关系，不是模型描述符合现实或原题。

## 不出图的计算入口

`action: "check"` 使用相同合同校验与事实计算，只返回回执，不创建展示节点；简单算术不必为了拿到计算结果而强行出图。数值回执另给 `zeroFillIllustration`：明确只是假设把 null 填成 0 的计算，不当成真实观测或完整总体。[-2,0,null,2] 的已观测均值和该假设均值都为 0，四次真实均值仍未知。

回执在交付之前检查为有界、可无损 JSON；单位为空的布尔事实用 null。此前布尔 unit 为 undefined 曾导致真实 DSH 输出拒绝并重试，首次失败和六个已交付视图完整保留，修复后 Native/PTC 对同类布尔回执通过。

## 实际验证

纯函数和真实 DSH Native/PTC 覆盖 300/50GB、空值/零、单位不一致、假来源标签、默认不推荐、本地键盘开启与撤销、范围/条件重置、640/360px 和刷新。Codex 的可选只读 MCP 适配复用同一个 core，见 [Codex 接入](CODEX.zh-CN.md)。精确测试、自然问题、候选 SHA 和最终安装证据见 VALIDATION 及 evidence；夹具不替代模型验收。

表单提交、用户动作回传、跨设备状态和任意图种仍未实现。偏好探索复选框是本地探索状态，不是这些能力的实现。

80 项测试通过。两轮新增完整原题与最后六题定点自然测试仍未完成语义验收：最终 D1 将“需要维护”误建成“支持维护”，D2 的预留控件只连偏好而没有激活容量硬要求；额外正文也有错误。程序能展示当次谓词，无法从任意语言标签自动证明业务映射。不要把硬要求表格当作原题已获认证。最终六题均保留失败，见 [完整索引](natural-question-results.json)。
