# 个人模板与主题（preview.6）

模板把已经确认的表达方式保存为可复用对象。模型可以查看和使用；命名、保存、更新、导入和删除由用户在界面完成。它不保证未来模型不会内置同类能力，价值要由第二次使用时节省的工作量检验。

## 使用

1. 在 DSH 的一张语义视图下面展开 **Templates & appearance**。
2. 调整明暗、Ocean/Forest/Berry 配色、字体、密度和字号。关系图还能选响应式、横向或纵向布局。预览立即作用于控件、表格、图表和关系图；不会修改原数据、单位、规则或静态摘要。
3. 填写模板名称，展开 **Review what will be saved** 查看保留的字段，再选 **Save as new template**。成功提示表示宿主存储写入已完成。
4. 选中模板后，使用 **Copy reuse instruction**，粘贴到新会话并补充新数据；也可以直接告诉模型“沿用我保存的某某模板，用以下新数据……”。模型通过 `templates` / `template` 查到真实 ID 和版本，再用 `render` 交付。
5. 主题可通过 **Use theme for future views** 设为当前 profile 的默认值。新生成的视图记录实际主题快照；旧消息不会跟着改变。

外观预览本身不保存：刷新后回到该消息生成时的样式。范围、系列开关、条件输入等探索状态仍在刷新后复位。模板库与这些临时操作状态是不同对象。

## 保存内容

| 组件 | 模板保留 | 每次重新提供 |
|---|---|---|
| ArchitectureExplorer | 组件类型、主题、布局方向 | 全部节点、边、职责、限制、场景和来源 |
| DecisionExplorer | 维度 ID/名称、条件字段 ID/类型/单位/可选项 | 新选项、各项事实/未知值、初始条件、规则、限制、来源 |
| DataChart 折线/柱图 | 图种、单位、横轴类型/时区/粒度/顺序、系列 ID/名称 | 标题、行和值、未知值、说明 |
| DataChart 直方图 | 图种、单位、计数或占比模式 | 分箱边界、组别、原始观测或预聚合计数、缺失量 |

不保存旧标题、摘要、实际数值、比较选项、条件初值、推理结论、证据或规则。规则复用需要额外的用户确认与语义设计，本版没有开放。字段名称、单位和枚举项仍可能包含私人信息，分享前必须检查预览；不能把“剥离数据”理解成自动匿名化。

新数据必须满足现有组件的完整 schema 和模板字段合同。字段 ID、类型、单位、顺序、图种不符会报错；显示名称允许更新。模板不会补齐旧值，也不会把缺失变成 0。统计和决策仍由当前数据重新计算。

## 版本、导出与错误

- **Save new version** 追加不可变版本；本版可修改名称和外观，字段合同从所选视图提取或从已有版本保留。改变字段结构时，先生成满足新需求的视图，再另存模板。
- **Make this version current** 只切换当前版本指针。继续编辑会追加新编号，既有版本不覆盖。每库最多 40 个模板、每模板 20 个版本；到限额可导出或另存副本。
- **Export saved version** 导出已保存版本，未保存的预览不在文件里。格式为 `dsh-semantic-ui-template`、版本 `1`；不是 DTCG/A2UI 兼容格式。
- **Import template file** 先校验并预览，再导入为新 ID；不覆盖同名模板。未知版本、额外字段、脚本/CSS/URL 配置、重复字段与超出 128 KiB 的文件会被拒绝。库总大小限制为 2 MB。
- 多页面编辑采用库 revision 比对。冲突时保留当前草稿，使用 **Reload library** 读取最新库后再决定保存，不能静默覆盖他人的编辑。
- 删除库中模板不会删除既有消息。历史 checkpoint 保存确切模板 ID、版本、名称和完整主题参数；即使库中对象被删，也能继续呈现。

## 宿主与数据边界

锁定 DSH 0.2.1-rc.2 的公开 `connection.fetch.register`、`connection.rpc.call` 和 `storageDomain` 接口。插件注册 `/api/dsh-semantic-ui/library` 精确入口，使用原生 RPC 信封/关联 ID，由宿主要求 profile owner；不占用 DSH 网关的单一 `/api` interceptor，不引入自定义登录或复制凭据。

默认 storage backend 位于 DSH HOME 的 storages 中，并非自动按 profile 分隔。本插件以公开 `profileContext.name` 的摘要命名独立 domain，隔离同一 HOME 中不同 profile 的模板。模板不进入源码或 Git。改名或切换 profile 不会自动迁移；可通过明确的导出/导入迁移。不提供云同步或多进程同时写同一 profile 的协调。

DSH 仍是唯一会话存储。库只保存模板和默认主题，不复制聊天。`generation: false` 停用模型工具/指引，保留旧内容和 owner 模板界面。全部禁用插件后历史原文仍存在，交互节点需要恢复 renderer 才能显示。

协议 1.1 增加受限 `presentation` 快照，并继续读取 1.0 历史。回退到 preview.5 时，1.1 节点会显示不支持版本的可读提示；不会悄悄重写为旧格式。要继续显示新节点，请恢复 preview.6 或兼容版本。

## 本轮验证

Native/PTC 的模板流程与重启恢复已验证；两个自然新会话成功复用模板并换入新数据，P2 的程序核算来源表述仍有备注，见 [本轮证据](evidence/templates.json)。单元测试覆盖版本、写入失败、冲突、导出内容、未知导入、profile 命名隔离、事实不变和调色板对比度。浏览器与真实模型结果分别记录在 [验证说明](VALIDATION.zh-CN.md) 和版本证据中；确定性夹具不能代替自然问题验收。表单回传、跨设备同步、任意页面编排和代码模板不在本版范围。
