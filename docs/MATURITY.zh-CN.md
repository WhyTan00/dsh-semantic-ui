# 成熟度与替代范围

评估日期：2026-10-23，0.1.0-preview.4。结论：适合作为三类解释任务的预览插件，仍有明确改进空间；不能全面、无损替代 GenUI。开源不代表已经完成全部语义验收。

preview.5 补充 [33 个项目的深入选型与采用记录](research/README.md)：目录外不再笼统优先 GenUI，而按实际工具能力选择。新增只读 capability catalog、原始条件下的决策求值回执及 ECharts ARIA 修复。下文 preview.4 的首次失败/复测仍是独立历史证据，没有被这轮研究覆盖；表单回传与生成应用仍未在本插件实现。

## 已有价值

关系、取舍和数值共用一个受限工具入口。模型负责选择表达并提供事实，组件负责方向/引用、声明式规则、缺失值和统计口径的一致性。正文外的原生聊天节点在工具过程折叠时仍可见，重启后从 DSH 自有会话记录恢复。局部操作不需要再次请求模型。

Native / PTC 的四样例生命周期、历史补页、重启和降级已分别验证。24 节点/45 边关系图验证到 360px 浏览器容器；没有把它外推成 80 节点复杂图或真实手机验收。详见 [验证说明](VALIDATION.zh-CN.md)。

## 这次评估落实的改进

- 收窄自己的生成指引：禁止输出的是本插件的 UI spec，不再把其他插件的围栏协议一并禁止。三个支持场景优先使用本工具，其他能力保留原插件的协议，同一视图不重复生成。
- 比较组件明确展示缺少的条件；把结果标为“规则结果”、来源标为“声明的来源”，静态摘要注明只对应原始条件、不会随本地控件重算，避免把模型拟定规则的结果包装成经过核实的事实或个人建议。
- 数值工具回执增加程序计算的 `dataFacts`：原始全量数据的首尾、最小/最大、均值、有效/缺失数量及相邻有效值下降次数。直方图明确分母和边界，超过 12 箱不展开每箱明细。它为正文提供核对依据，不自动证明模型正文正确。
- 把完整自然测试记录与截图分离为独立证据包，安装包仍保留紧凑索引和验证说明。原始首次失败继续随开源代码和证据包公开；减少的是安装下载量，不是测试记录。

## 真实共存测试揭示的边界

同时开启本插件与公开 `@changfenhuang/dsh-genui@0.14.0`，使用个人 WorkBuddy 的 `deepseek-v4.1-flash / high`，四个新会话中：架构、比较、趋势分别选择本插件；报名表选择 GenUI，均未重复生成另一套视图。表单的主题、昵称和备注经真实提交回传下一轮模型。它证明这组样例能分工，不能证明所有问题都会稳定选择正确插件。

首次趋势回答虽然图表正确，正文却把低点 3°C 说成高于起点 4°C。增加数值回执后的同题新会话实际收到了 `firstValue=4, minimum=3, lastValue=6`，正文正确描述了回落；原失败和定向复测分别保留。单次复测不证明通用准确率或提示的因果效果。

表单回答还承诺刷新不丢失，实测未提交的勾选和文本会复位；重新填写后提交回传成功。此处区分控件能力、状态持久化和模型承诺。比较回答仍在未知成本/迁移条件下过早推荐方案，架构正文额外否定了未给出的反向调用。这些都没有被结构校验解决。完整记录见 [共存测试索引](evidence/genui-model-coexistence.json)。

preview.5 的另一个生成表单实例在等待 1000ms 后刷新，主题/备注得到保留，但仅填备注的提交承诺不成立。它与上述 C4 的实例和时序都不同，所以没有把任一观察升级为所有 GenUI 表单的规则。比较回执已被模型实际读到，正文仍有语义失败。详见 [定向复核](evidence/ecosystem-adoption.json)。

## 与 GenUI 的分工

| 需求 | 本插件 | 具体 GenUI |
| --- | --- | --- |
| 关系方向、路径、邻域探索 | 专门的 ArchitectureExplorer | 有通用流程/Mermaid 等表达，协议不同 |
| 条件比较、未知值、硬约束 | 专门的 DecisionExplorer | 有卡片/表格等通用展示 |
| 时间序列、类别柱图、等宽直方图 | 显式数据口径、源表和确定性操作 | 有更广的通用图表展示 |
| 表单、测验、3D、操作回传模型 | 未实现 | 白名单 GenUI 包含相应能力 |
| 生成 React 应用、模拟器、应用状态 | 未实现 | 另一类生成应用的 GenUI 提供；其 DSH 版本范围需另行核实 |
| 已有 GenUI 历史 | 不接管、不迁移 | 继续由原 renderer 读取 |

上表的 GenUI 指两类具体公开实现，不能混为一个产品；版本、公开源码和实测范围见 [GENUI](GENUI.zh-CN.md)。建议保留原插件读取旧历史，在三类支持场景优先选择本插件，超出目录的交互交给合适的原插件。当前上游白名单 GenUI 没有独立关闭全部生成指引同时保留 renderer 的公开开关，仍有指引竞争。

## 下一步最值得投入的地方

后续产品讨论已将个人模板/主题与换数据复用列为下一版主线，之后接通有界表单。当前完整排序与未实现边界以 [采用合同](research/ADOPTION.zh-CN.md) 为准；下面的内容语义和真实使用问题仍需持续修正。

1. 优先提高比较规则与用户事实的对应，避免把未知偏好、成本和未来计划变成默认推荐；扩大负例并保持首次结果可追溯。
2. 扩大跨插件自然问题覆盖，核对“选了哪种表达”和“内容是否正确”两项独立结果；探索与上游约定生成指引/历史 renderer 的明确开关。
3. 如确有需求，再设计带明确确认边界的操作回传与状态持久化；它会改变当前“本地探索”的产品范围，不适合通过隐藏副作用补上。
4. 补充真实手机、更多宿主版本和复杂图的实际阅读体验。目前的 360px 是浏览器容器证据。

最近一轮完整的 11 题仍有 4 条内容语义失败；本次四题共存及单题复测没有替换这份完整验收，也没有把项目升级为稳定版。安装、校验和及可回退的版本以个人 [Release](https://github.com/WhyTan00/dsh-semantic-ui/releases) 为准。
