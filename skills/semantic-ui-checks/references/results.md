# Explicit saved results

Use `semantic_ui_result_check` for an explicitly supplied complete DSH result document. It reads result formats 1–5 with the existing parser; an envelope-only tool cannot validate the outer result package. Preserve its returned `document` and checksum, locale/theme/layout, source record, nulls, A/B values, selected scenario and unapplied draft. The returned document uses the same DSH contract and can be carried back to a compatible DSH; the checker does not save or overwrite a library.

Supply the complete candidate in `answer` when checking a proposed explanation. Structured matching, a supported assertion, diagnostic spans and saved checksums never approve the candidate or the remaining words in a sentence. `wholeCandidateVerified` stays false. A `limited-delivery` result permits only `answerDelivery.text`, the existing finite program-derived projection of the independently selected source. Preserve its origin and scope; do not describe it as a repaired or verified original model answer. Missing source, mismatch, stale `expectedBinding`, incomplete source scope or unsupported projection cannot deliver candidate text. Recompute after any source, view/rule, mapping or candidate change; the returned binding includes checker contract and hashes. A caller-supplied answer is not proof that the host's complete body was intercepted.

The result tool separates original declarations, deterministic calculations, local hypotheses and the saved historical source record. A is a retained local snapshot; B and its draft remain separate. Invalid draft text is not an applied numeric value, zero or false. Do not use model annotations, saved source hashes or a declared `bound` status as identity, approval or a fresh source check.

An optional `mapping` compares only the original view against the source snapshot configured by the caller when the server started. It reuses the advertised finite source grammar. Tool arguments and package fields cannot select another file, kind, account or source. A mismatch, missing source, unsupported scope or changed historical source digest remains explicit. Finite field matching does not verify arbitrary prose or world facts. Never silently substitute A/B values for original source conditions.

The current companion's `dist/result-local.js --result-file … --answer-file …` is the existing direct in-process consumer, compiled with its dependencies; it needs no MCP connection. Its `--emit grounded` prints only the finite source projection and fails without one. The older `dist/result-readonly.js` and repository `examples/codex-readonly.py --result-package … --plugin-package … --plugin-manifest …` use actual stdio MCP; do not call them when new connections are excluded. Neither path creates a Codex thread, starts a model or reads global Codex settings. Use only caller-provided files; no directory search, global plugin installation, source replacement, tool/model fallback or approval is implied. `--emit document` prints unchanged unverified data for migration, never a certified answer. Without an independently configured source, describe the report as unverified, even when the package checksum is valid.

CLI/MCP execution is distinct from native Codex tool registration, model natural adoption, rich UI or DSH rendering. Report only the layer actually exercised.
